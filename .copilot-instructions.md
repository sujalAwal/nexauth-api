# NexAuth API - Architecture & Coding Patterns

This document defines the standard architecture and patterns that all modules in the NexAuth API must follow.

---

## 1. Module Architecture - Three-Tier Pattern

All feature modules must implement a **three-tier architecture**:

### Tier 1: Repository (Database Access)
**Location:** `app/modules/{module}/repositories/{entity}_repository.py`

**Responsibility:** Database operations only (queries, persistence, lookups)

**Rules:**
- No business logic
- No HTTP concerns
- Pure database queries
- Accept SQLAlchemy Session in `__init__`
- Return ORM models (not DTOs)
- Methods are database-focused: `get_by_id()`, `create()`, `update()`, `delete()`, `get_all()`, etc.

**Example:**
```python
class UserRepository:
    def __init__(self, db: Session):
        self.db = db
    
    def get_by_id(self, user_id: UUID) -> User | None:
        return self.db.query(User).filter(User.id == user_id).first()
    
    def create(self, entity: User) -> User:
        self.db.add(entity)
        self.db.commit()
        self.db.refresh(entity)
        return entity
```

---

### Tier 2: Service (Business Logic)
**Location:** `app/modules/{module}/services/{entity}_service.py`

**Responsibility:** Business rules, validation, transformation, orchestration

**Rules:**
- Contains all domain logic
- Receives DTOs (Pydantic schemas) as input
- Returns DTOs as output (not ORM models)
- Uses Repository for database access
- No direct database queries
- Validates inputs before any side effects
- Raises `ValueError` for business logic errors
- Handles pagination, filtering, and complex operations
- Keep business rules testable and independent of HTTP

**Example:**
```python
class UserService:
    def __init__(self, db: Session):
        self.db = db
        self.repo = UserRepository(db)
    
    def create_user(self, request: UserCreateRequest) -> UserResponse:
        # Validation FIRST (no side effects before this)
        if self.repo.email_exists(request.email):
            raise ValueError("Email already exists")
        
        # Business logic (hash password, etc.)
        hashed_pwd = self.hash_password(request.password)
        
        # Persist
        new_user = User(email=request.email, password=hashed_pwd)
        saved = self.repo.create(new_user)
        
        # Return DTO (not ORM model)
        return UserResponse.model_validate(saved)
```

---

### Tier 3: Controller (HTTP Handlers)
**Location:** `app/modules/{module}/controllers/{entity}_controller.py`

**Responsibility:** HTTP concerns only (routing, request parsing, response formatting, status codes)

**Rules:**
- No business logic (all business rules in Service)
- Delegates to Service
- Handles HTTP status codes
- Catches Service exceptions and converts to HTTP responses
- Uses `BackgroundTasks` for async operations (only AFTER service succeeds)
- Returns `ApiResponse` generic wrapper
- No direct database queries

**Example:**
```python
@user_router.post('/')
def create_user(
    request: UserCreateRequest,
    background_tasks: BackgroundTasks,
    db: Session = Depends(get_db)
):
    try:
        service = UserService(db)
        user_response = service.create_user(request)
        
        # Background task ONLY after service succeeds
        background_tasks.add_task(send_email, user_response.email)
        
        return ApiResponse(
            success=True,
            message="User created successfully",
            data=user_response
        )
    except ValueError as e:
        return ApiResponse(
            success=False,
            message=str(e),
            errors={"validation": str(e)}
        )
```

## 3. Request/Response DTO Patterns

### Request Schemas (Input Validation)

**Location:** `app/modules/{module}/schemas/requests/{entity}_request.py`

**Rules:**
- Use Pydantic `BaseModel`
- Separate `{Entity}CreateRequest` and `{Entity}UpdateRequest` classes
- Include field validators for business rules
- Never include IDs from URL paths in request body
- Use `EmailStr`, typed fields, and descriptions

**Example:**
```python
class UserCreateRequest(BaseModel):
    email: EmailStr = Field(..., description="User's email")
    name: str = Field(..., min_length=1)
    password: str = Field(..., description="Password (min 8 chars, 1 letter, 1 digit)")
    
    @field_validator('password')
    def validate_password(cls, value):
        if len(value) < 8:
            raise ValueError("Password must be at least 8 characters")
        return value


class UserUpdateRequest(BaseModel):
    email: EmailStr = Field(..., description="User's email")
    name: str = Field(..., min_length=1)
    # Note: NO password field (separate endpoint for password change)
    # Note: NO id field (comes from URL path)
```

### Response Schemas (Output Formatting)

**Location:** `app/modules/{module}/schemas/response/{entity}_response.py`

**Rules:**
- Use Pydantic `BaseModel` with `ConfigDict(from_attributes=True)`
- Represent ORM models as DTOs
- Never expose sensitive fields (passwords, secrets)
- Include timestamps and status fields
- Create separate `{Entity}Collection` for list responses

**Example:**
```python
class UserResponse(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    
    id: UUID
    name: str
    email: EmailStr
    is_active: bool
    created_at: datetime
    updated_at: datetime
    # Note: NO password field (never expose to client)


class UserCollection(BaseModel):
    users: list[UserResponse]
```

## 4. Error Handling Pattern

### Service Error Strategy
- Raise `ValueError` for business logic errors (validation, not found, etc.)
- Include clear error message

### Controller Error Strategy
- Catch `ValueError` → return 400 Bad Request with validation errors
- Catch unexpected exceptions → return 500 Internal Server Error
- Always return `ApiResponse` (consistent format)

**Pattern:**
```python
try:
    service = UserService(db)
    result = service.create_user(request)
    return ApiResponse(success=True, data=result)
except ValueError as e:
    return ApiResponse(success=False, message=str(e), errors={"validation": str(e)})
except Exception as e:
    return ApiResponse(success=False, message="Operation failed", errors={"error": str(e)})
```

## 6. Pagination Pattern

### Request Parameters
Use the standard `ListRequestFilters` from `app.schemas.request`:

```python
from app.schemas.request import ListRequestFilters

@router.get('/items')
def list_items(
    filters: ListRequestFilters = Depends(ListRequestFilters),
    db: Session = Depends(get_db)
):
    service = ItemService(db)
    result = service.get_paginated(filters)
    return ApiResponse(
        success=True,
        data=result["data"],
        paginations=result["pagination"]
    )
```

### Service Implementation
```python
def get_paginated(self, params: ListRequestFilters) -> dict:
    query = self.db.query(Item)
    
    result = self.query_handler.execute_paginated_query(
        query=query,
        params=params,
        searchable_fields=[Item.name, Item.description],  # Use column objects
        sortable_fields=["created_at", "updated_at"]
    )
    
    return {
        "data": [ItemResponse.model_validate(item) for item in result["data"]],
        "pagination": result["pagination"]
    }
```

## 8. Common Patterns by Operation

### Create Operation
```
Controller POST /items
  ↓ validates schema
  → Service.create_item(request: CreateRequest)
    ↓ validates business rules (duplicates, etc.)
    → Repository.create(entity)
      ↓ saves to DB
    ← returns ORM model
  ← returns ItemResponse DTO
← return ApiResponse[ItemResponse]
```

### Read Operation
```
Controller GET /items/{id}
  ↓ validates path parameter
  → Service.get_item(item_id: UUID)
    ↓ validation
    → Repository.get_by_id(item_id)
    ← returns ORM model or None
  ← returns ItemResponse DTO or None
← return ApiResponse[ItemResponse]
```

### Update Operation
```
Controller PUT /items/{id}
  ↓ validates schema + path parameter
  → Service.update_item(id: UUID, request: UpdateRequest)
    ↓ validates business rules (not found, conflicts, etc.)
    ↓ updates ORM model
    → Repository.update(entity)
      ↓ saves changes
    ← returns ORM model
  ← returns ItemResponse DTO
← return ApiResponse[ItemResponse]
```

### List Operation
```
Controller GET /items
  ↓ parses query parameters
  → Service.get_paginated(params: ListRequestFilters)
    ↓ builds query with filters
    ↓ applies pagination
    → Repository operations
    ← returns [ORM models]
  ← returns [ItemResponse] DTOs
← return ApiResponse[ItemCollection]
```

## 9. Password Hashing (Security)

### Current Implementation
Uses PBKDF2-SHA256 (built-in, no dependencies):
```python
import hashlib, secrets

def hash_password(password: str) -> str:
    salt = secrets.token_hex(32)
    pwd_hash = hashlib.pbkdf2_hmac('sha256', password.encode(), salt.encode(), 100000).hex()
    return f"pbkdf2_sha256${salt}${pwd_hash}"

def verify_password(stored_hash: str, provided: str) -> bool:
    algorithm, salt, pwd_hash = stored_hash.split('$')
    provided_hash = hashlib.pbkdf2_hmac('sha256', provided.encode(), salt.encode(), 100000).hex()
    return pwd_hash == provided_hash
```

### Upgrade Path
For production, migrate to bcrypt:
```bash
pip install bcrypt
```

Then update Service:
```python
import bcrypt

def hash_password(password: str) -> str:
    return bcrypt.hashpw(password.encode(), bcrypt.gensalt()).decode()

def verify_password(stored_hash: str, provided: str) -> bool:
    return bcrypt.checkpw(provided.encode(), stored_hash.encode())
```

## 14. MSSQL Database Compatibility

### Important: Avoid SQLAlchemy `exists()` Function

MSSQL has limitations with SQLAlchemy's `exists()` function. Use simple query patterns instead:

**❌ DON'T USE (causes MSSQL syntax error):**
```python
from sqlalchemy import exists
return self.db.query(exists().where(User.email == email)).scalar()
```

**✅ USE INSTEAD (MSSQL-compatible):**
```python
# For existence checks
return self.db.query(User).filter(User.email == email).first() is not None

# For existence checks with exclusion
query = self.db.query(Entity.name).where(Entity.name == name)
if exclude_id:
    query = query.where(Entity.id != exclude_id)
return query.first() is not None
```

### Pattern for All Repositories

All `*_exists()` methods should use the pattern:
```python
def name_exists(self, name: str, exclude_id: UUID = None) -> bool:
    """Check if name already exists (MSSQL-compatible)."""
    query = self.db.query(Entity.name).where(Entity.name == name)
    if exclude_id:
        query = query.where(Entity.id != exclude_id)
    return query.first() is not None
```

This works across all database backends (MSSQL, PostgreSQL, MySQL, SQLite) and avoids syntax errors.

## 15. Quick Checklist for New Modules

When creating a new feature module, ensure:

- [ ] Repository created with database methods only
- [ ] Service created with business logic and validation
- [ ] Controller created with HTTP handlers only
- [ ] Request schema created with proper validators
- [ ] Response schema created without sensitive fields
- [ ] Error handling follows pattern (ValueError → ApiResponse)
- [ ] All responses wrapped in `ApiResponse` generic
- [ ] Database session passed to Service `__init__`
- [ ] Pagination uses column objects (not strings)
- [ ] Password/secrets hashed before storage
- [ ] Validation happens BEFORE side effects
- [ ] Imports organized by concern (models, schemas, services)
- [ ] No direct `db.query()` calls in controller
- [ ] No HTTP concerns in service/repository
- [ ] **MSSQL Compatibility**: Use `.first() is not None` instead of `exists()`

## Summary

| Layer | Responsibility | Input | Output | Direct DB |
|-------|---|---|---|---|
| **Controller** | HTTP routing & status codes | HTTP request + query params | `ApiResponse` | ❌ No |
| **Service** | Business rules & validation | Request DTO | Response DTO | ❌ No |
| **Repository** | Database operations | SQLAlchemy objects | ORM models | ✅ Yes |

**Golden Rule:** If it's business logic, it goes in Service. If it's DB access, it goes in Repository. If it's HTTP, it goes in Controller.

## 16. Public API Pattern (Customer-Facing)

The public API provides read-only access to curated data for customers/external consumers. Unlike admin APIs, public endpoints use a **2-tier architecture** (Service + DTO only, no repository layer).

### Directory Structure
```
app/modules/public/
├── {module}/
│   ├── controllers/
│   │   └── {entity}_public_controller.py
│   ├── services/
│   │   └── {entity}_public_service.py
│   └── schemas/
│       └── response/
│           └── {entity}_public_response.py
```

### Public Service Pattern (Read-Only, Reuses Admin Models)

**Key Differences:**
- Services directly query admin models (no admin repo dependency)
- Only GET operations
- Filters data based on business rules (is_active, is_featured, etc.)
- Transforms ORM models to public DTOs (restricted field set)

**Example:**
```python
class ProductPublicService:
    def __init__(self, db: Session):
        self.db = db
    
    def get_products_paginated(self, search: str = None, category_id: UUID = None, 
                                min_price: Decimal = None, max_price: Decimal = None) -> list[Product]:
        """Get active products with dynamic filtering."""
        query = self.db.query(Product).filter(Product.is_active == True)
        
        if search:
            search_term = f"%{search}%"
            query = query.filter(Product.title.ilike(search_term))
        
        if category_id:
            query = query.filter(Product.category_id == str(category_id))
        
        if min_price is not None:
            query = query.filter(Product.price >= min_price)
        
        if max_price is not None:
            query = query.filter(Product.price <= max_price)
        
        return query.order_by(Product.display_order).all()
    
    def increment_visit_count(self, product_id: UUID) -> None:
        """Track product views."""
        product = self.db.query(Product).filter(Product.id == product_id).first()
        if product:
            product.visit_count += 1
            self.db.add(product)
            self.db.commit()
```

### Public Response DTO Pattern (Restricted Fields)

**Rule:** Never expose: `created_by`, `updated_by`, `deleted_by`, `created_at`, `updated_at`, `deleted_at`

**Example:**
```python
class ProductPublicBasicResponse(BaseModel):
    """List view - minimal fields for performance."""
    model_config = ConfigDict(from_attributes=True)
    
    id: UUID
    title: str
    price: Decimal
    thumbnail_url: Optional[str] = None
    brand_id: Optional[str] = None
    category_id: str

    title: str
    name: str
    sku: str
    price: Decimal

    # ... more fields, but NO audit/timestamp fields
```

### Public Controller Pattern (GET-Only Endpoints)

**Rules:**
- Only `GET` operations
- No request body parsing (queries only)
- Increment visit_count on detail view
- Return consistent `ApiResponse[T]` wrapper

**Example:**
```python
product_public_router = APIRouter()

@product_public_router.get("/", response_model=ApiResponse[ProductPublicBasicCollection])
def list_products(
    search: str = None,
    category_id: UUID = None,
    brand_id: UUID = None,
    min_price: Decimal = None,
    max_price: Decimal = None,
    db: Session = Depends(get_db)
):
    """Get filtered products with advanced search."""
    try:
        service = ProductPublicService(db)
        products = service.get_products_paginated(search, category_id, min_price, max_price)
        
        return ApiResponse(
            success=True,
            message="Products retrieved",
            data=ProductPublicBasicCollection(
                data=[ProductPublicBasicResponse.model_validate(p) for p in products]
            )
        )
    except Exception as e:
        raise HTTPException(status_code=400, detail=str(e))


@product_public_router.get("/{product_id}", response_model=ApiResponse[ProductPublicFullResponse])
def get_product_by_id(product_id: UUID, db: Session = Depends(get_db)):
    """Get product details with auto-incremented visit count."""
    try:
        service = ProductPublicService(db)
        product = service.get_product_by_id(product_id)
        
        if not product:
            raise HTTPException(status_code=404, detail="Product not found")
        
        service.increment_visit_count(product_id)  # Track views
        
        return ApiResponse(
            success=True,
            message="Product retrieved",
            data=ProductPublicFullResponse.model_validate(product)
        )
    except HTTPException:
        raise
    except Exception as e:
        raise HTTPException(status_code=400, detail=str(e))
```

### Key Patterns

1. **Dual Responses:** List endpoints return basic DTOs (performance), detail endpoints return full DTOs
2. **Auto-Increment Views:** Call `increment_visit_count()` on detail view
3. **Dynamic Filtering:** Build WHERE clauses in service based on query parameters
4. **No Audit Fields:** Public responses never include timestamps or user references
5. **Active Filter:** All public queries filter by `is_active == True` by default
6. **Reuse Admin Models:** Don't duplicate entity definitions, query admin models directly
7. **2-Tier Only:** Public API skips repository layer (DB queries directly in service)
